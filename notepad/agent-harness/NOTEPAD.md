# Notepad harness SOP

## Target

Windows Notepad (`C://Windows//System32//notepad.exe`), Windows 11.

## Flavor

GUI-only. REA's native-UI observation is macOS-only, so this harness was
built by driving Windows UI Automation directly: the tree is captured live,
every action is gated, and every action records before/after evidence.

## Commands

```bash
cli-anything-notepad ui-tree                          # dump the live UIA tree (read-only)
cli-anything-notepad ui-menus                         # list expandable menu paths (read-only)
cli-anything-notepad ui-invoke "<path>" --yes         # invoke one element
cli-anything-notepad ui-select "<path>" --yes         # select one element (tab, list item)
cli-anything-notepad ui-set-text "<path>" "<text>" --yes   # set a Value element's text
```

All commands support `--json`. Paths accept any unique suffix of the full
UIA path, so callers do not need to track the window title (which changes
with the unsaved-changes marker).

## Safety model

- `ui-tree` / `ui-menus` are read-only.
- Every driving action requires `--yes`.
- Paths matching save/close/delete/remove/exit/quit/format/discard/
  overwrite/replace are refused even with `--yes` unless the runner is
  invoked with `--allow-destructive`.

## Requirements

- Windows
- `pip install uiautomation` (the harness's `utils/uia_runner.py` is
  self-contained; it needs only this package)

## Risks

- UIA is a live tree: paths go stale when the UI changes. Re-run `ui-tree`
  rather than trusting a stored path.
- Driving another app's GUI mutates that app's state. The `--yes` gate and
  the destructive-path refusal are the guardrails; review actions before
  enabling them.
