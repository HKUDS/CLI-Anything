### E2E plan (`test_full_e2e.py`)

Layers: (a) backend wrapper against the real binary, (b) intermediate files (settings JSON, 3MF
structure), (c) true-backend slices verified programmatically, (d) installed-CLI subprocess tests.

Verification methods: G-code header magic `; generated by OrcaSlicer`, extrusion-move count,
`max_z_height`, layer count vs. `ceil(height / layer_height)`, filament weight monotonicity,
nozzle temperature `M104 S…` lines, ZIP integrity of 3MFs, PNG magic bytes + dimensions,
STL dimensions measured by OrcaSlicer's own `--info`.

### Realistic workflow scenarios

1. **Draft vs. fine quality sweep** — *Simulates:* choosing a quality preset for a prototype.
   *Chain:* new project → add 20×10×30 box → slice at 0.28 mm → slice at 0.08 mm.
   *Verified:* layer counts ≈ 30/0.28 and 30/0.08, print time increases with finer layers.
2. **Print-orientation change** — *Simulates:* laying a tall part on its side to remove supports.
   *Chain:* rotate-x 90 → slice. *Verified:* `max_z_height` drops 30 → 10 (proves the
   automatic `--ensure-on-bed` guard; without it OrcaSlicer prints 5 mm).
3. **Scaling for a different size** — scale 2 → `max_z` 60, filament ≈ 8× baseline.
4. **Strength tuning** — infill 10 % vs 60 % vs *Strength* preset → filament grams strictly increase.
5. **Material swap** — PLA vs PETG vs ABS → `M104 S` temperatures in the G-code match preset.
6. **Batch production** — `repetitions 2` → filament ≈ 2× and two objects in statistics.
7. **3MF hand-off round trip** — export sliced 3MF → validate ZIP → import the 3MF as a model in a
   new project → slice again → G-code produced.
8. **STL post-transform export** — scale 2 + export STL → `--info` reports 2× size.
9. **Vendor-style preset inheritance** — synthetic `inherits` chain on disk → flattened → sliced.
10. **Preview loop** — capture `quick` (PNG thumbnails from OrcaSlicer), cache hit on repeat,
    change layer height, `preview diff` reports layer-count change; `preview latest` doesn't render.
11. **Agent session** — one-shot subprocess commands with `--json`: new → add → set → slice → stats;
    auto-save persists, `--dry-run` doesn't, undo works in REPL-less mode via file reload.
12. **Failure handling** — unknown setting, bad value, missing model, unknown preset,
    `--strict` + `--no-check`, and backend exit-code decoding (missing file → `CLI_FILE_NOTFOUND`).
