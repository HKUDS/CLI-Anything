# Bluesky harness SOP

## Target

Bluesky / AT Protocol — `https://bsky.social/xrpc` (public API, docs at
docs.bsky.app). No local software required.

## Flavor

local-server (documented web API). Harness-forge scaffolded this harness from
the public API documentation; the auth flow and request bodies were completed
by hand against the documented protocol.

## Commands

```bash
cli-anything-bluesky login [--handle H] [--app-password P]  # session via App Password
cli-anything-bluesky whoami                                # current handle/did
cli-anything-bluesky post "text"                           # create one post
cli-anything-bluesky timeline [--limit N]                  # home timeline
cli-anything-bluesky profile [actor]                       # profile
cli-anything-bluesky search "query" [--limit N]            # search posts
cli-anything-bluesky endpoints                             # XRPC map
```

All commands support `--json`.

## Auth model

Bluesky App Passwords (Settings -> App Passwords), never the account password.
Credentials come from `--handle`/`--app-password`, `BSKY_HANDLE`/
`BSKY_APP_PASSWORD`, or an interactive prompt — never from a positional arg,
so they stay out of shell history and process listings. The session token is
written to `~/.config/cli-anything-bluesky/session.json` with 0600 permissions
(override with `CLI_ANYTHING_BLUESKY_SESSION`). Nothing is baked into code.

## Risks

- `post` writes to a live public network. It is the only mutating command;
  there is no bulk-post or delete surface by design.
- Rate limits are the API's own; the harness surfaces HTTP errors verbatim.
